# Task: FB-016 - Say which dates a report covers

Status: Ready for implementation
Risk: medium (captions next to report figures; no data or arithmetic changes)
Implementer: Claude Code (Opus). The plan names Antigravity; the owner handed wave 2 to this session on
November 6, 2026.
Review: fresh Claude Code review (Opus, subagent), review-task skill

Source: DX-08 in `docs/driver-experience-plan.md`.

## Objective

With **All time** selected, the line under the Reports range button reads like "3 shifts · Sep 6, 2026 – Nov 3, 2026
· expenses included by date · export includes these". It looks as if the report covers Sep 6 – Nov 3, but estimated
net also includes a Nov 6 fuel receipt: All time counts every expense, whatever its date. The caption should name the
period actually selected, keep the shifts' own dates separate, and say plainly which expenses count.

  `applyPreset` (presets set `from`/`to`; All time sets neither).
- `flexbuddy/src/main/resources/static/js/reports.js`: `rangeLabel`, `summaryLine`, the export at the bottom.

  `js.app.beginning`, `js.app.today` (also used elsewhere; keep), `js.schedule.shifts.*`.

## Current behavior

- All time: "{n} shifts · {first shift date} – {last shift date} · expenses included by date · export includes these".
- A preset or custom range: "{n} shifts · {from} – {to} · ...", with "Beginning" / "Today" for an open end.
- A station: "... · {station} · expenses linked to these shifts only · ...".
- Behavior (unchanged by this task): with no dates every expense counts; with dates, expenses dated in the range
  count; with a station, only expenses linked to that station's blocks count. The shift CSV export uses the same
  filters and contains shifts only.

## Required behavior

1. A pure `scopeLine(filterState, shifts, formatDate)` in `reports.js` (exported with the other helpers) builds the
   line; `updateResultSummary` uses it. The parts, in order:
   - **Period**: "All dates" with no dates; "{from} – {to}" with both; "From {from}" or "Until {to}" with one.
   - **Shifts**: the count, plus their own date span when there are any: "3 shifts, Sep 6 – Nov 3, 2026" (one date:
     "1 shift, Sep 6, 2026"); "No shifts" when there are none.
   - **Station**, when one is chosen.
   - **Expenses**: with a station and dates, "only expenses dated in this period and linked to {station} blocks
     count"; with a station only, "only expenses linked to these shifts count"; otherwise, with no dates, "every
     expense counts, whatever its date, except ones on blocks still scheduled"; otherwise "expenses dated in this
     period count, except ones on blocks still scheduled".
   - **Export**: "the CSV export has these shifts", or "... except forfeited ones" when forfeited blocks are listed
     (the export uses `ShiftStatus.EARNINGS`). (Expense and export wording updated after the FB-016 review.)
2. Every date is formatted by the page's `formatDate` from the `YYYY-MM-DD` strings; nothing uses `toISOString()`.
3. Old keys used only by the old line are removed from both catalogs; new keys go in the `js.reports` group.

## Out of scope

- The data: filters, totals, which expenses count, the export's contents.
- The range button label (`rangeLabel`) and the stations line (`summaryLine`).

## Acceptance criteria

- [ ] All time names "All dates" as the period, shows the shifts' own span separately, and says every expense counts
      whatever its date.
- [ ] A preset or custom range names that range, and says expenses dated in it count; open ends read "From" /
      "Until".
- [ ] A period with no shifts (expenses only) says "No shifts" and still describes which expenses count.
- [ ] A station filter says only expenses linked to these shifts count.
- [ ] The export part matches the export (shifts only, same filters); no total, filter or export changes.
- [ ] English and Spanish; `SpanishMessagesTest` passes.
