## Current behavior

Shared GoalProgress.of computes remaining, percent, pace, on-track and blocks-to-go from already prepared values.
ShiftReportService still prepares the 90-day sample, average block pay/minutes, historical net/gross kept share
and scheduled pay on the selected goal basis. Its separate scheduleSnapshot computes next-seven-days planned
count/minutes/gross pay and overdue scheduled blocks needing confirmation. These are distinct projections:
period goal planned pay includes every scheduled block in the goal period, while the upcoming-work projection
only includes blocks in today..today+6 whose end is strictly after account-local now.

The published library and server dependency are 0.2.0. Its shared plain Block already includes status, date/times,
base pay, tips and miles. Existing FigureInputs supplies the server mapping. No new runtime dependency is needed.

## Required behavior

### Shared goal preparation

- Add a small immutable plain-input API in importcore.figures for preparing goal history and goal planned pay.
  Reuse existing Block, NetEarnings and GoalProgress; avoid a framework, entity dependency or parallel
  calculator. Choose the smallest useful types and document the caller's input-selection responsibilities.
- Keep database access, signed-in-user selection, account settings, countable-expense/link filtering, DTO mapping
  and account-local clock resolution on the server. The helper reads no clock, locale, time zone, database or I/O.
  Accept today/local now explicitly. Expose the 90-day inclusive history boundary through the shared API so a
  future Android adapter need not invent its own history-window constant.
- Preserve the history range today-89 through today inclusive. History earnings include the server report's live
  completed/cancelled rows and countable expenses by their own dates. The denominator and minutes sample include
  only COMPLETED blocks. Do not silently replace the historical earnings numerator with completed-only earnings;
  cancelled earnings and unlinked expenses can affect it under existing behavior.
- Average pay uses the chosen gross/net history total divided by the completed-block count, cents HALF_UP.
  Average minutes preserves the existing Math.round(float totalWorkedMinutes / completedCount) behavior.
  Both averages are null with zero completed sample blocks, even if cancelled earnings/expenses exist.
- Gross-basis planned pay uses scheduled base pay only. Net basis multiplies the raw scheduled base-pay sum by
  historical net/gross share, rounded to four decimal places HALF_UP. Zero historical gross uses share ONE.
  Preserve negative or greater-than-one historical shares; do not introduce clamps or new estimate policies.
  Preserve rounding order: pass the unrounded multiplied planned amount into existing GoalProgress.of, which
  performs remaining/on-track/blocks-to-go and final money rounding. Do not round each scheduled block first.
- Keep Monday-Sunday weekly and calendar-month periods, nullable targets and the chosen basis and the existing no-target
  short-circuit (no shift/expense reads). No-goal responses, null averages and all existing DTO values/scales remain
  unchanged. The server may keep existing period/query selection and supply prepared shared earnings results,
  completed history blocks and period scheduled blocks to the helper; the arithmetic itself belongs in the JAR.

### Shared planned-work summary

- Extract the shared pure preparation of plannedShifts, plannedMinutes, expectedPay and needsConfirmation from
  scheduleSnapshot. Accept that account's live scheduled Block inputs and explicit account-local now.
- Planned count/minutes/gross pay cover today through today+6 inclusive, only when the block end is strictly after
  now. Use the existing shared duration/overnight rules to match Shift.getEndDateTime, including equal times.
  A previous-day overnight block is not included in planned merely because it ends today.
- Needs-confirmation includes scheduled blocks dated on/before today whose end is at/before now, including rows
  older than the upcoming or 90-day windows. At exact end time it needs confirmation, not upcoming work.
- Scheduled tips never enter planned pay. Scheduled blocks remain excluded from confirmed earnings/hours/net;
  planned minutes are a separate figure. Preserve zero/empty behavior and returned money scales.
- Keep cancelled/forfeited/late-forfeit counts and monthly status queries on the server; those diagnostics are not
  needed for this bounded extraction. Preserve the remaining ScheduleSnapshot fields unchanged.

## Security and regression risks

Every server query still uses the signed-in email; plain library inputs deliberately carry no account identity.
Wrong caller selection can change averages or let a scheduled block affect confirmed earnings. Goal planned pay
and upcoming gross pay have different time filters and must not be conflated. Rounding order, null/zero semantics,
negative estimates and the completed-only denominator are observable existing behavior. Preserve them even when
an alternative looks cleaner. Test data must be synthetic. Never print credentials, real driver records or private
calendar links. Publishing 0.3.0 is a separate explicit owner approval after the reviewed source is merged.
