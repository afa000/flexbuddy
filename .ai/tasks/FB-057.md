## Current behavior

The website exposes `GET /standing?days=90` (`StandingController`), which delegates to `StandingService.window(email, days)`
for `days` in `7..365` inclusive (default `90`), returning `StandingResponse(from, to, current, entries, events)`:

- `to` is today in the signed-in account's time zone (`UserTimeService.today`); `from` is `to.minusDays(days - 1L)`.
- `entries` begins with the carry-in entry in force on `from` (the latest entry with `recordedOn < from`, keeping its
  original `recordedOn` date), if any, followed by entries logged within `[from, to]` inclusive in ascending
  `recordedOn` order.
- `current` is the driver's latest logged entry overall (even if older than `from`), or `null` if nothing was ever logged.
- `events` lists the driver's non-deleted `FORFEITED` and `CANCELLED` blocks with `date` in `[from, to]` inclusive,
  ordered oldest first (`date` ascending, `startTime` ascending), classifying each as `LATE_FORFEIT`, `FORFEITED`, or
  `CANCELLED`.
- On the website, enum values serialize in upper case (`GREAT`, `LATE_FORFEIT`) and `LocalTime` serializes with seconds
  when present; invalid `days` returns localized plain text via `GlobalExceptionHandler`.
- API v1 currently has no Standing endpoint. `docs/native-app-plan.md` NA-13's status note also still lists the app
  halves of step 4 (FB-054, CSV export) and step 2 (FB-056, Reports) as open.

## Required behavior

- Add `GET /api/v1/standing` in a new `ApiStandingController` under `com.angel.flexbuddy.api`, registered only when
  `flexbuddy.api.enabled=true` (`@ConditionalOnProperty(name = "flexbuddy.api.enabled", havingValue = "true")`).
  With the property off/unset, the controller bean is absent, every HTTP method on `/api/v1/standing` returns `404`
  without a `Location` header, and the website endpoints and security chain are unchanged.
- Enforce bearer-token-only authentication via the existing `/api/v1/**` stateless security chain: missing, malformed,
  unknown, expired, or revoked tokens—and requests carrying only a website session cookie—return `401`
  `{"error":"unauthorized"}` with no `ETag` or redirect, before any standing lookup or conditional check runs.
- Scope strictly to the authenticated `Principal.getName()`. Ignore any caller-supplied account selector parameters.
- Accept optional query parameter `days` as a `String` (following `ApiTaxSummaryController`'s `year` pattern):
  - When omitted (`days == null`), default to `90`.
  - When present, parse as a base-10 `int` (`Integer.parseInt`) and pass to `StandingService.window(email, days)`, which
    enforces `7..365` inclusive and throws `InvalidStandingException` outside that range.
  - Any malformed value (non-integer, empty, whitespace, decimal, hex, integer overflow, or repeated parameter) or
    out-of-range value (`< 7` or `> 365`) returns JSON `400` `{"error":"invalid","fields":{"days":"invalid"}}` with no
    `ETag` header (via a controller-local `@ExceptionHandler(InvalidStandingException.class)` so `GlobalExceptionHandler`
    never intercepts it with plain text).
- Map `StandingResponse` through a dedicated package-private `ApiStanding` DTO (`from`, `to`, `current`, `entries`,
  `events`, with nested `Entry(recordedOn, level, note)` and `Event(date, startTime, station, kind)`):
  - `from`, `to`, `recordedOn`, `date`: ISO local dates (`YYYY-MM-DD`) via `ApiValues.date`.
  - `startTime`: `HH:mm` local time with no seconds via `ApiValues.time`.
  - `level`: lowercase `StandingLevel` codes via `ApiValues.code` (`fantastic`, `great`, `fair`, `at_risk`).
  - `kind`: lowercase `StandingEventKind` codes via `ApiValues.code` (`forfeited`, `late_forfeit`, `cancelled`).
  - Preserve `null` `current` (when nothing was ever logged) and `null` `note` (when unset/blank), preserve the carry-in
    entry before `from` with its real `recordedOn` date followed by in-window entries ascending, and preserve exact
    event ordering and exclusions from `StandingService.window`.
  - Never serialize entities directly, and never log bearer tokens or driver standing entries/notes.
- Use `ApiEtags.withEtag(mapper, ApiStanding.of(...), request)` for conditional reads:
  - Strong SHA-256 `ETag` and `Cache-Control: private, no-cache` on both `200` and `304`.
  - Matching authenticated `If-None-Match` returns `304` with an empty body.
  - Any change to the returned standing entries, in-window block events, or account-zone local date returns `200` with
    the updated JSON and a new `ETag`. No delta cursor is supplied.
- Update `docs/api-v1.md` with a `### GET /api/v1/standing` section documenting the optional `days` query parameter,
  made-up example 200 JSON, every field, lowercase enum codes, nullability (`current`, `note`), carry-in entry and event
  ordering semantics, status codes (`200`, `304`, `400`, `401`, `404`), and per-account-and-window conditional caching.
- Update the NA-13 status note in `docs/native-app-plan.md` to record that FB-054 (offline CSV export, step 4) and
  FB-056 (offline Reports, step 2) are merged, leaving only step 6 open in NA-13.

## Acceptance criteria

- [ ] With `FLEXBUDDY_API_ENABLED=true`, `GET /api/v1/standing` matches `GET /standing` for equivalent made-up accounts
      and windows, including empty standing (`current: null`, empty `entries`/`events`), a carry-in entry before `from`
      with its real `recordedOn` date, `null` vs populated `note`, all four lowercase standing levels, and `forfeited`,
      `late_forfeit`, and `cancelled` events in ascending `date`/`startTime` order with `HH:mm` times (and excluding
      scheduled, completed, and soft-deleted blocks).
- [ ] Omitting `days` defaults to `90`, inclusive bounds `7` and `365` succeed, and malformed or out-of-range `days`
      values return `400 {"error":"invalid","fields":{"days":"invalid"}}` with no `ETag`.
- [ ] `from` and `to` follow the account's local time zone across midnight; crossing local midnight shifts the window
      and invalidates the previous day's `ETag`.
- [ ] Missing or invalid bearer tokens and web-session-only requests (even with a valid `If-None-Match`) return `401`
      `{"error":"unauthorized"}` with no `ETag`. Two accounts see only their own standing data, ignoring query selectors
      and another account's `ETag`.
- [ ] With the API disabled (`flexbuddy.api.enabled` unset/false), `ApiStandingController` is not registered, all HTTP
      methods on `/api/v1/standing` return `404` without a `Location` header, and website routes behave unchanged.
- [ ] Matching `If-None-Match` returns `304` with an empty body, matching `ETag`, and `Cache-Control: private, no-cache`.
      Logging/updating/removing a standing entry or changing/soft-deleting a forfeited/cancelled block in the window
      returns `200` with updated JSON and a new `ETag`.
- [ ] `docs/api-v1.md` documents `GET /api/v1/standing` completely and `docs/native-app-plan.md` NA-13 reflects that
      FB-054 and FB-056 are merged.

## Security and regression risks

- Standing entries contain private driver notes and account standing history, and events expose station/schedule
  details. Authenticate bearer tokens before running `StandingService` or checking `If-None-Match`, scope every query
  strictly to `Principal.getName()`, keep `Cache-Control: private, no-cache`, and never log tokens, entries, or notes.
- Preserve website `GET /standing`, `PUT /standing/{recordedOn}`, `DELETE /standing/{recordedOn}`, and
  `GlobalExceptionHandler` behavior completely unchanged.
