# Task: FB-001 - Add Node tests for the toast notification script

Status: Ready for implementation

## Objective

`flexbuddy/src/main/resources/static/js/toast.js` shows the small notice that appears after saving or deleting
(for example "Shift deleted" with an Undo button). Drivers rely on Undo to recover a mistaken delete, but the script
has no tests, so a change to it could break Undo without anything failing.

## Current behavior

`toast.js` exports `window.flexbuddyToast = {init, show, hide, isVisible}`. `app.js` and `account.js` call `init` with
the selectors of the toast in `templates/shifts.html` (`#successToast`, `#toastTitle`, `#toastMessage`, `#toastAction`,
`#toastCountdown`) and then `show(title, message, options)`.

- `show` does nothing until `init` found the toast element.
- Notices queue: a second `show` waits until the first is hidden, then appears 100 ms later.
- A notice hides itself after `options.duration` ms (3500 by default); hovering or focusing it pauses the timer.
- `options.alert` gives the toast `role="alert"`; otherwise it is `role="status"`.
- The action button is hidden unless `options.onAction` is given. Its label is `options.actionLabel`, or "Undo".
- Clicking the action hides the notice and runs `onAction`. If `onAction` throws, a new alert notice says
  "Undo failed" with the error's message.
- Escape hides the visible notice.

## Required behavior

Add `flexbuddy/src/test/js/toast.test.js` that tests the behavior above. Follow the existing tests in
`flexbuddy/src/test/js/` (for example `reports.test.js` and `feedback.test.js`):

- Load the script with `loadScript('toast.js', extra)` from `./load-script`. `extra` can replace `document`,
  `setTimeout` and `clearTimeout`; the script calls `window.setTimeout`, and `window` is the context itself.
- Use small fake elements (`textContent`, `setAttribute`/`getAttribute`, a `classList` with `add`, `remove`, `toggle`
  and `contains`, `addEventListener`, `contains`, `style`, `onclick`, `offsetWidth`) and a fake `document` whose
  `querySelector` returns them and which records `keydown` listeners.
- Control time with fake `setTimeout`/`clearTimeout` that store callbacks so the test can run them, rather than
  waiting for real timers.
- The English strings you need are `js.common.undo=Undo` and `js.toast.undoFailed=Undo failed`; `loadScript` already
  loads them, so `t()` works inside the script. Do not open `messages.properties`: it is 84 KB, too large for a
  local model's context.
- Write the test file in steps: create it with the first two or three tests, run them, then add the rest.
- Objects created inside the script come from another realm; compare primitives, as `load-script.js` explains.

## Out of scope

- Any change to `toast.js` or another file in `src/main/`. If a test shows a real bug, describe it in the handoff
  report instead of fixing it.
- The countdown bar's CSS animation beyond checking that it doesn't throw.

## Design references

None.

## Acceptance criteria

- [ ] `show` before `init` does nothing and `isVisible()` stays false.
- [ ] After `init`, `show` fills the title and message, removes `is-hidden` and sets `role="status"`.
- [ ] `alert: true` sets `role="alert"`.
- [ ] Without `onAction` the action button has `is-hidden`; with it, the button shows "Undo", or `actionLabel` when
      given.
- [ ] A notice hides after its duration; a second notice queued meanwhile appears 100 ms after the first hides.
- [ ] Escape hides the visible notice.
- [ ] Clicking the action runs `onAction` once and hides the notice; when `onAction` rejects, an alert notice
      "Undo failed" shows the error message.
- [ ] `node --test "src/test/js/*.test.js"` passes from `flexbuddy/`, including the new file.

## Validation

From the repository root: `.\scripts\verify.ps1 -TaskId FB-001`. The Java suite should be unaffected. No browser or
emulator checks: nothing the driver sees changes.

## Security and regression risks

None for drivers: test-only change. The risk is a test that passes without checking anything, so each acceptance
criterion needs an assertion that would fail if the behavior broke.
