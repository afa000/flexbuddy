## Objective

app must build the same files offline (NA-13 step 4) so a driver gets an identical export with no signal. This is the
server half: move the two CSV writers into `com.angel:flexbuddy-import-core` with plain inputs, and have the website
use them, with output unchanged. The Android export screen is a separate app task.

## Current behavior

GET export endpoints in ShiftController and ExpenseController select the signed-in driver's rows with the page's
filters and stream them through Spring `@Component` writers that take `ShiftResponse` / `ExpenseResponse`.

- Blocks CSV: UTF-8 with a BOM, CRLF line ends, 31 fixed headers, a cell quoted only when it contains a comma, quote,
  CR or LF. Money is two decimals HALF_UP (null money prints `0.00`, except `actual_hourly_rate`, which prints empty);
  other decimals strip trailing zeros; times `HH:mm`; instants ISO-8601; `hours_worked` is minutes / 60 at two
  decimals HALF_UP; `late_forfeit` prints only for FORFEITED blocks. Only the station is guarded against spreadsheet
  formulas (a leading `=`, `+`, `-`, `@`, tab or CR gets a `'` prefix). Missing details use `BlockDetailsResponse.NONE`.
  The writer flushes and leaves the stream open.
- Expenses CSV: UTF-8 with no BOM, CRLF, header `Date,Category,Amount,Note,Shift ID,Station`, every cell quoted, the
  category as its enum name, the amount as `BigDecimal.toString()`, and any cell starting with `=`, `+`, `@` or `-`
  gets a `'` prefix (so a negative amount does too). The writer closes the stream.

These differences between the two files are existing behavior and stay.

## Required behavior

1. In import-core, add a new package `com.angel.flexbuddy.importcore.export` with:
   - immutable record inputs `ShiftCsvRow` (every value a blocks CSV row prints, already computed: id, date, station,
     scheduled times, minutes worked, base pay, tips, total, hourly rate, miles, mileage cost, linked expenses, net
     pay, net hourly rate, earnings per mile, created/updated instants, status name, the details fields and the late
     forfeit flag) and `ExpenseCsvRow` (date, category name as a string, amount, note, block id, station);
   - `ShiftCsv` and `ExpenseCsv` with a `write(List<row>, OutputStream)` that produces exactly the bytes described

   The library only formats. It computes no earnings, reads no clock, locale or zone, and has no Spring or other
   dependency. Status is passed as its name string, and the FORFEITED rule compares that name. It must pass
   AndroidApiCompatibilityTest (API 26).

## Security and regression risks

The export is the driver's own earnings record, often used for taxes, so any byte change (a lost BOM, a different
rounding, a changed quote rule) is a regression. Keep the formula-injection guards exactly as they are; don't
"improve" them here. Selection stays in the server's user-scoped services; the library must never receive or select
another account's rows. Use made-up data only in fixtures; never commit a real export.
