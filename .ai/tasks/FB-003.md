# Task: FB-003 - Read recent Flex screenshots accurately

Status: Ready for implementation

## Objective

Screenshot import has been getting fields wrong or leaving them empty, mostly on recent screenshots. Drivers then
retype times, station or pay by hand, or import a shift with the wrong hours. Import should read the screenshots Flex
shows today correctly.

## Current behavior

`POST /shifts/import/preview` (`ShiftImportService`) runs `ScreenshotPreprocessor` (grayscale, invert if dark, one
global Otsu threshold), `TesseractScreenshotTextExtractor`, then `ShiftScreenshotParser`. Measured against 178
screenshots with values read by eye (the owner's own captures plus public driver posts), 626 of 853 fields are right
(73%); on the owner's 60 screenshots, 269 of 295 (91%). The misses:

- Flex now leaves out ":00" on the hour (`16:30 - 21`, `19 - 22`, `5:30 p.m. - 8 p.m.`, `12 AM - 12:30 AM`). The
  parser only accepts `HH:MM - HH:MM`, so start and end come back empty.
- On a dark-mode card (Block details), the global threshold turns the grey card and its text into one black block, so
  date, times and pay are lost.
- Offer cards wrap `11:45 AM -` and `2:45 PM` onto two lines, often with the pay beside the first.
- `Orders (Any)` is read as station `ANY`; OCR reads `VEA6` as `VEAG`.
- Day-first dates (`Monday 27/02`, `domingo 18/10`), US Spanish month-first dates (`martes, 07/28`), dates with no
  comma (`MONDAY FEBRUARY 7`), the Spanish end label `Finalizar a las`, and pay written `£47.50`, `MXN 397` or
  `51,00 GBP` are missed or misread.

## Required behavior

- Accept time ranges where either side drops the minutes, in 24-hour or 12-hour form, including a range wrapped onto
  the next line. A range with no minutes on either side needs a duration on its line, so ZIP codes and similar numbers
  are not read as times.
- Let Tesseract binarise the grayscale image with its adaptive (Sauvola) method instead of one threshold for the whole
  image.
- A station code must contain a digit; a four-character code ending in a digit look-alike letter is corrected.
- Numeric dates use the order that makes a real date; when both do, day first for British (£/GBP) and Mexican Spanish
  screenshots, month first otherwise and for zero-padded US Spanish ones. A weekday and month name need no comma.
- Read `Finalizar a las` as the end label and pay in £, € and MXN as well as $.
- Add an opt-in test that measures field accuracy on a local folder of screenshots and a CSV of expected values, both
  kept outside the repository.

## Out of scope

Multiple shifts from one screenshot, a currency field on shifts, UI changes, the warning rules, and the scheduled-shift
matching. No new dependencies.

## Design references

None. The sample screenshots are private and stay in the owner's Dropbox; expected values are in
`.ai/artifacts/FB-003/` (ignored by Git).

## Acceptance criteria

- [ ] All 295 fields right on the owner's 60 screenshots.
- [ ] At least 95% of fields right on all 178 labelled screenshots.
- [ ] New parser unit tests cover each format above with made-up data.
- [ ] Existing parser, preprocessor and import tests still pass.

## Validation

`.\mvnw.cmd -B -ntp verify` from `flexbuddy/`. The accuracy test runs only when `FLEXBUDDY_OCR_SAMPLES` (and
`FLEXBUDDY_OCR_LABELS`) are set; CI does not run it, because CI has no native Tesseract. Production builds Tesseract
5.5.3, which supports `thresholding_method`. Upload a screenshot locally at http://localhost:8080 to check the preview.
No JavaScript, template or migration changes.

## Security and regression risks

No per-user data, earnings rules, migrations, backup/restore or catalogs change. Screenshots and expected values are
real drivers' data and must not be committed. Sauvola thresholding runs in Tesseract's native memory in tiles; the
Java heap use of preprocessing goes down because the Java threshold pass is removed.
