# Task: FB-006 - Take the Bouncy Castle 1.85 security fixes

Status: Ready for implementation
Risk: medium
Implementer: Claude Code

## Objective

GitHub Dependabot reports two open alerts on `main` for `org.bouncycastle:bcprov-jdk18on` below 1.85, both fixed in
1.85:

- **Critical**, CVE-2026-8763 (GHSA-9pwp-9qqc-pr26): Name Constraints bypass via a trailing dot in rfc822Name and URI.
- **High**, CVE-2026-13506 (GHSA-qp49-qgx5-5m26): forcing a lazy ASN.1 sequence resets the nesting-depth guard.

Neither is reachable in FlexBuddy today (see the risks below), but the library sits on the push reminder path and the
alerts stay open until production runs 1.85.

## Current behavior

Checked against `origin/main` at 2091872.

- `flexbuddy/pom.xml` declares `bcprov-jdk18on` 1.84 directly. Only `WebPushGateway` uses it: it registers
  `BouncyCastleProvider` (appended last, so it is never the default provider) for the `web-push` 5.1.1 library, which
  loads the VAPID keys and encrypts push payloads with it.
- `tess4j` 5.20.0 pulls `bcpkix-jdk18on` and `bcutil-jdk18on` 1.84 through `pdfbox-tools` → `pdfbox-debugger` 3.0.8.
  FlexBuddy never opens PDFs; OCR works on images only.
- Spring Boot 4.1.2 does not manage Bouncy Castle versions.

`mvnw dependency:tree -Dincludes=org.bouncycastle` today:

```
com.angel:flexbuddy:jar:0.0.1-SNAPSHOT
+- net.sourceforge.tess4j:tess4j:jar:5.20.0:compile
|  \- org.apache.pdfbox:pdfbox-tools:jar:3.0.8:compile
|     \- org.apache.pdfbox:pdfbox-debugger:jar:3.0.8:compile
|        \- org.bouncycastle:bcpkix-jdk18on:jar:1.84:compile
|           \- org.bouncycastle:bcutil-jdk18on:jar:1.84:compile
\- org.bouncycastle:bcprov-jdk18on:jar:1.84:compile
```

- Dependabot's PR afa000/flexbuddy#9 raises `bcprov-jdk18on` alone. That would leave `bcpkix` and `bcutil` at 1.84
  beside `bcprov` 1.85. Bouncy Castle ships its modules as one release and expects them to match.
- No test builds `WebPushGateway`, so nothing in the suite runs Bouncy Castle. `PushServiceTest` mocks the gateway.

## Required behavior

1. In `flexbuddy/pom.xml`, add a `bouncycastle.version` property set to `1.85`.
2. The direct `bcprov-jdk18on` dependency uses `${bouncycastle.version}`.
3. Add a `dependencyManagement` section that pins `bcpkix-jdk18on` and `bcutil-jdk18on` to `${bouncycastle.version}`,
   so the `tess4j` path resolves to 1.85 too, with a short comment saying why.
4. Add `WebPushGatewayTest` covering the one code path that uses Bouncy Castle, with made-up keys and no network:
   - a freshly generated VAPID key pair makes the gateway configured and returns the public key;
   - an invalid key leaves push disabled instead of failing startup;
   - a payload for a made-up subscription encrypts into a request with the `aes128gcm` content encoding and a VAPID
     `Authorization` header (`PushService.preparePost`, which `send` uses before the HTTP call).
5. Change no other dependency or version.

## Out of scope

- Upgrading `web-push`, `tess4j` or `pdfbox`.
- Removing `pdfbox-tools` from `tess4j` with an exclusion. It would drop the Bouncy Castle copies the app never uses,
  but tess4j's PDF helpers would break if they were ever called. See the open questions.
- Any change to push reminders, OCR, two-step sign-in, CI, `render.yaml` or Android.
- Closing PR #9. The owner does that after this merges.

## Security and regression risks

- **Reachability:** the Name Constraints flaw is in Bouncy Castle's certificate path validation, and the ASN.1 flaw in
  its ASN.1 parser. FlexBuddy never validates certificates or parses ASN.1 with Bouncy Castle: the provider is
  registered last, so Java's own TLS and certificate checks still run first. The VAPID keys and subscription keys are
  raw EC points, and the `bcpkix` copy is only on tess4j's unused PDF path.
- **Push reminders:** if 1.85 broke VAPID key loading, push would turn off quietly rather than fail startup. The new
  `WebPushGatewayTest` and production check 2 catch that.
- **Two-step sign-in:** `TwoFactorSecretCipher` uses Spring Security's `Encryptors.delux` (Java's AES/GCM), not Bouncy
  Castle. `FLEXBUDDY_TWO_FACTOR_KEY` is unchanged, so stored authenticator secrets still decrypt.
- **Sign-in, per-user data, earnings, migrations, backup/restore, catalogs and Android:** untouched.
