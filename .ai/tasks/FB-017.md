# Task: FB-017 - Recognizable deleted expenses, and expenses linked to a deleted block

Status: Ready for implementation
Risk: high (a production failure on Expenses and Reports; which expenses count toward net and tax figures)
Implementer: Claude Code (Opus). The owner handed wave 2 to this session on November 6, 2026.
Review: fresh Claude Code review (Opus, subagent), review-task skill

Source: DX-09 in `docs/driver-experience-plan.md`, plus a bug found while preparing it.

## Bug (reproduced on localhost, 2026-11-06; same code is in production)

`Shift` has `@SQLRestriction("deleted_at is null")` and `Expense.shift` is a lazy `@ManyToOne`. When a block with a
linked expense is deleted (moved to Recently deleted), anything that reads that expense's shift beyond its id throws
`org.hibernate.ObjectNotFoundException` and the endpoint returns 500 until the block is restored, or purged after 30
days (the FK is `on delete set null`). Reproduced:

- linked block deleted, expense live: `GET /expenses` 500, `GET /shifts/statistics` 500, `GET /expenses/export.csv`
  500 (`/expenses/summary` 200); restoring the block brings them back;
- expense and its block both deleted: `GET /expenses/trash` 500 (the Recently deleted expenses list).

Dereferences that trigger it (`getShift().getStation()` / `.getStatus()`): `ExpenseService.toResponse`,
`ShiftReportService.addExpense` and `reportExpenses`, `TaxService` (station at ~191, status at ~220),
`BlockEvaluator` (~155). `getShift().getId()` is safe (no proxy load).

## Owner decision (2026-11-06)

While a linked block is in Recently deleted, its expenses **count toward net by their date**, like unlinked expenses
(the same as after the 30-day purge), and are labeled as linked to a deleted block. Restoring the block re-links them.

## Required behavior

1. **One batch lookup, no proxy loads.** A native `ShiftRepository` query returns `id, station, status, deleted_at`
   for a set of shift ids owned by the user, ignoring `@SQLRestriction`. `ExpenseService` exposes it as a map for a
   list of expenses (one query per list, never per row). Every place listed above uses it instead of
   `getShift().getStation()/getStatus()`.
2. **Counting.** An expense is left out of net only when its linked block exists, isn't deleted, and is `SCHEDULED`
   (today's rule). Linked to a deleted block: counts by date, grouped as unlinked (no station) in reports and tax.
3. **Responses.** `ExpenseResponse` gains `shiftDeleted` (last field): true when the link points to a deleted block;
   `station` is that block's station.
4. **DX-09 rows.** Recently deleted expense rows show category, amount, date, the linked station (or "deleted block"),
   and the note: escaped as text, one line with ellipsis, full text in `title`. Restore and Delete permanently stay
   distinct and tappable at phone width. The main expense list shows the same "deleted block" tag.
5. Unchanged: deletion/purge semantics, the 30-day window, ownership scoping, backup format.

## Acceptance criteria

- [ ] With a linked block deleted, Expenses, Recently deleted, Reports statistics and earnings, tax summary, block
      evaluator and the expense CSV export all load (no 500), for live and deleted expenses.
- [ ] Such an expense counts by date in net, with no station; restoring the block re-links it and it groups by
      station again.
- [ ] Expenses on a live scheduled block still wait; every other figure is unchanged (existing tests untouched).
- [ ] Trash rows identify similar expenses by note and station; notes render as text.
- [ ] Lookups are one query per list, scoped to the user. English and Spanish.
