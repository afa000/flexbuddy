# Task: FB-015 - Say that forfeiting here only updates FlexBuddy

Status: Ready for implementation
Risk: low (localized copy only)
Implementer: Claude Code (Opus). The plan names OpenCode + local model; the owner handed wave 2 to this session on

Source: DX-06 in `docs/driver-experience-plan.md`.

## Objective

Schedule's **Forfeit** button and its confirmation read as if FlexBuddy forfeits the block with Amazon. It only
records the status in FlexBuddy; the block stays on the driver's Amazon Flex itinerary until they forfeit it in the
Amazon Flex app. A driver who trusts the button can miss a block they meant to drop, or keep one they think is gone.

## Files to read

- `flexbuddy/src/main/resources/static/js/schedule.js`: the Next up card's actions (`js.schedule.forfeit`), the
  confirm strip's "Forfeited" answer, and `confirmForfeit` (normal and late variants).
- Catalog keys: `js.schedule.forfeit`, `js.schedule.forfeitThisBlock`, `js.schedule.forfeitMessage`,
  `js.schedule.forfeitBlock`, `js.schedule.lateForfeitMessage`, `js.schedule.forfeitAnyway`,
  `js.schedule.markCancelled` (the wording to match), `js.common.forfeited`.

## Current behavior

- Next up: "Forfeit" next to "Mark cancelled". Confirmation: "Forfeit this block? ... will be marked forfeited. It
  earns nothing and counts toward this month's forfeits." Button: "Forfeit block".
- Inside the forfeit window: "Late forfeit ... may affect your standing. Forfeit anyway?" Button: "Forfeit anyway".
- Spanish says "Perder el bloque" throughout.

already happened.
