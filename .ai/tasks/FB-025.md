## Objective

A reported earnings screenshot shows Total $90.50, Base $72.00 and Tips $18.50. Import currently takes the first
currency amount as base pay, then adds tips, inflating the driver's earnings to $109.00. Read the labels so the preview
contains base $72.00 and tips $18.50, totaling $90.50 when confirmed by the driver.

## Current behavior

ShiftScreenshotParser uses the first PAY_PATTERN match anywhere as base pay. Its Tips/Propinas matcher only reads
a dollar amount on the same line. A total or tip encountered before base can therefore become base pay. The import
preview exposes the parser's fields and confidence/source-line metadata. Saving remains subject to driver review.

## Required behavior

1. Prefer an explicit Base/Base pay label, including Spanish Pago base/Importe base/Ganancias base, over earlier
   Total or Tips/Propinas amounts. Match whole labels case-insensitively.
2. Read labeled amounts on the same line or on the immediately following nonblank OCR line. A value must not cross
   another money label. Handle several labeled amounts on one OCR line.
3. Read Tips/Propinas separately, using the existing currency formats; absent tips still default to zero.
4. Keep the existing first-amount fallback for schedule/offer screenshots without a Base or Total breakdown.
   Never use an amount belonging to Tips/Propinas as that fallback, including when tips appear first.
5. If a Base/Total breakdown is present but base cannot be read, return missing base and retain the existing editable
   preview/missing-base warning. Do not infer base by subtracting tips from total or silently accept total as base.
6. Preserve the amount's source line index and do not raise confidence above either its label or amount evidence.
7. No existing record is changed. Driver review/status rules, scheduled-shift earnings exclusions, other parsed fields,
   duplicate handling and save endpoints stay unchanged.
