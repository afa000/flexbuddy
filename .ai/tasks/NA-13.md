## Objective

The native app should show this week's figures, reports and "Is this offer worth it?" with no signal, and get the
same numbers the website shows. That only holds if the phone and the server run one implementation of the figures.
This task is step 1 of NA-13: move the calculators and the earnings rules they depend on into the shared plain-Java
library, with the server delegating to it and every figure staying exactly as it is today. Publishing the new
version and the app screens are later tasks; this task alone changes nothing a driver sees.

Source: docs/native-app-plan.md, NA-13 step 1. NA-12 (library, publishing, app import) has merged; import core
0.1.2 is published and pinned by the app.

## Current behavior

The figures live in Spring beans in `com.angel.flexbuddy.service`:

- `GoalProgressCalculator` (goal progress, pace, blocks to go), `PayPeriodCalculator` (pay periods from payout
  weekdays and a lag), `IrsMileageRates` (dated IRS rate table) and `MileageRates` (custom or IRS rate) depend on
  nothing but a `@Component` annotation and server DTOs.
- `NetEarningsCalculator` takes `Shift` and `Expense` entities and returns `NetEarningsResult`. It relies on the
  entity's earnings rules: a null status counts as completed; base pay counts for completed and cancelled blocks;
  tips and hours only for completed; miles for every status except scheduled. Scheduled blocks never count toward
  earnings, hours or net.
- `ExpenseService.countable` leaves out an expense linked to a block that is still scheduled (`LinkedShift.waiting`);
  an expense on a deleted block counts by its date.
- `BlockEvaluator` mixes queries (worked blocks at a station, linked expenses, fuel and maintenance over a window,
  account settings) with pure arithmetic: choosing the sample (station's last 90 days with at least 3 blocks, then
  its whole history, then the account), per-minute rates, the usual base rate per hour, surge, the offer estimate
  run through `NetEarningsCalculator`, the difference percent and the verdict. The sample is in the report filter's
  date-descending order, and a station basis reports the first (newest) block's trimmed station name.
- The shared library `com.angel:flexbuddy-import-core:0.1.2` holds only screenshot import rules. It runs on the app
  from Android 8 (API 26). `BlockEvaluator` today calls `Stream.toList()` and `List.getFirst()`, which Android below
  API 34 and 35 lacks.

## Required behavior

### Shared figures in the library

- Add the figures to `flexbuddy/import-core` in a new package, `com.angel.flexbuddy.importcore.figures` (see Owner
  decisions), as plain Java 21 with no runtime dependencies, no Spring, no persistence, no clock, locale or time zone
  reads. "Today" and every date are explicit inputs. Amounts stay `BigDecimal` with today's scales and rounding modes.
- Plain inputs instead of entities:
  - a block: status (null meaning completed, as today), date, start and end time, base pay, tips, miles, and the
    station where the evaluator needs it;
  - a cost: category, amount, date;
  - for a linked expense, whether its block is still scheduled and not deleted (the waiting rule).
- Library enums for block status (`SCHEDULED`, `COMPLETED`, `CANCELLED`, `FORFEITED`), cost category (`FUEL`, `TOLL`,
  `PARKING`, `MAINTENANCE`, `OTHER`), vehicle cost method, evaluation basis and verdict, with the same constant names
  as the server's. The server maps by name. A server test fails if a server enum gains a constant the library
  doesn't have, so a new status can't silently fall through.
- Move, with their behavior unchanged:
  - the block earnings rules listed under Current behavior (time worked across midnight, counts toward earnings,
    hours and miles, earned base pay, tips and pay, worked minutes, counted miles);
  - the expense waiting rule;
  - `GoalProgressCalculator`, `PayPeriodCalculator` (including `parseDays` and `formatDays`), `IrsMileageRates`
    (same table and dates) and `MileageRates`;
  - `NetEarningsCalculator`, returning a library result with the same 17 figures;
  - the pure part of `BlockEvaluator`: sample choice from the driver's worked blocks, rates, usual base hourly,
    surge, the offer and usual estimates, difference percent and verdict, the newest-block station label, and the
    fuel and maintenance spread per mile or per minute. The library receives already-selected lists; station
    comparison for the sample is case-insensitive equality like the repository's `lower()` on stored station names.
- Library results are immutable and carry no translated text and no database ids.

### Server delegates, figures unchanged

- One implementation of each rule. The server keeps its existing classes, public signatures and DTOs as thin adapters
  that map values and delegate; no copied arithmetic stays in the application. This includes `Shift`'s earnings
  methods and `LinkedShift.waiting()`, which delegate to the library rule rather than keeping a second copy.
- `NetEarningsCalculator.calculate(List<Shift>, List<Expense>, VehicleCostMethod, MileageRates)` and
  `GoalProgressCalculator.progress(...)` keep their signatures and return the same DTOs. `IrsMileageRates`,
  `MileageRates` and `PayPeriodCalculator` (including the nested `Period` record) keep their server names and public
  methods, because existing tests and `AccountSettingsResponse`/`AccountRestoreService` call them.
- `BlockEvaluator` keeps its constructor, `evaluate(email, request)`, its queries, account scoping, transaction and
  the static `usualBaseHourly(List<Shift>)` used by its test. It maps the query results to plain inputs, calls the
  library, and maps back to `BlockEvaluationResponse`.
- Every response shape, rounding, ordering and null stays as today on the website, `/api/v1/**`, reports, taxes,
  goals and the offer evaluator. `ShiftReportService` and `TaxService` keep their queries; they get the same numbers
  through the adapter.

### Android compatibility

- The new library code must run on API 26. Don't use `Stream.toList()`, `Matcher.results()` or the Java 21
  sequenced-collection methods (`getFirst`, `getLast`, `removeFirst`, `removeLast`, `addFirst`, `addLast`,
  `reversed`), which Android lacks below API 35. Extend `AndroidApiCompatibilityTest` to refuse the sequenced-
  collection calls as well.

## Security and regression risks

These calculators produce every earnings, hours, net, mileage and goal figure on the website today, with the API off,
so the move must be exactly equivalent; the unchanged tests and the before/after comparison are the proof. The
scheduled-never-counts rule must hold in the library itself, because the app will call it without the server's
queries in front of it. Queries, ownership and account scoping stay on the server: the library never sees an email,
user id or another driver's blocks. Tax figures stay on the server (`TaxService` reads payments and settings the
phone may not have). No migration, backup format or Recently deleted change. The rounding of money and miles, and
`BigDecimal` scales, must not change: a scale change alters JSON (`12.5` versus `12.50`) and CSV output.
