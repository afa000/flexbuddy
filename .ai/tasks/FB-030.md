# Task: FB-030 - Antigravity's Gemini 4 models as equals in the agent workflow

Status: Ready for implementation
Risk: low (workflow docs and the agent guard; no app code)
Implementer: Claude Code (Opus), owner request November 12, 2026
Review: fresh Codex (Sol) or Antigravity (Gemini 4 Argon) session, review-task skill

## Objective

The owner wants Antigravity with Gemini 4 Argon and Gemini 4 Hydrogen to stand level with Claude Code and Codex: Argon
in the Opus/Sol role, Hydrogen in the Sonnet/Terra role. Today AGENTS.md bars Antigravity from high-risk work and the
agent guard only runs in Claude Code and Codex. The companion task FB-031 does the same in flexbuddy-android.

## Files to read

- `AGENTS.md`: "How work is organised" (skills, implementer and risk lines) and "Deployment" (the guard line).
- `docs/agent-workflow.md`: the intro, "Starting a task in Codex", "The loop", "The native app's repository", "The
  guard", "Antigravity Pro", "Which tool for which task", "Saving tokens", "A task from start to merge" and
  "Running everything from one Claude Code session".
- `.ai/tasks/TEMPLATE.md` (Implementer and Review lines), `.agents/skills/review-task/SKILL.md` (last paragraph).
- `scripts/hooks/guard.mjs`, `scripts/hooks/guards.test.mjs`, `.codex/hooks.json` as the pattern for a new tool.
- `scripts/run-agent.ps1`: the `$Model` parameter and the Antigravity arguments.
- Antigravity's hook contract: the CLI's built-in `agy-customizations` skill, `docs/hooks.md`. Workspace hooks load
  from `<workspace>/.agents/hooks.json`; a `PreToolUse` hook gets `toolCall.name` and `toolCall.args` (for example
  `run_command` with `CommandLine`, `write_file` with `Path`) on stdin and answers `{"decision":"deny","reason":...}`
  on stdout. Its stored arguments are JSON-encoded strings.

## Current behavior

- AGENTS.md: high-risk work is "implemented by Claude Code (Opus) or Codex (Sol), never by Antigravity or a local
  model". The workflow doc treats Antigravity as a helper for medium work "when usage is tight".
- The guard refuses pushes to `main`, `gh pr merge` and edits to committed migrations in Claude Code and Codex only.
- `run-agent.ps1 -Agent antigravity` can't choose a model.

## Required behavior

- Three equal tools, two tiers: Opus/Sol/Argon (top) and Sonnet/Terra/Hydrogen (routine). High-risk work needs a top
  model; plans and reviews use a top model, in any of the three tools.
- `.agents/hooks.json` runs `guard.mjs antigravity` before every Antigravity tool call: release check on any
  `CommandLine`, migration check on any non-read tool's `*Path`/`*File` argument. It answers `deny` or prints nothing,
  never `{}` (Antigravity reads that as a deny) or `allow`, so its own permission rules keep deciding everything
  else. Unreadable input prints nothing.
- `run-agent.ps1 -Model <agy model id>` passes `--model` to Antigravity; the local default stays `gemma4:12b-32k`.
- The docs say how to start each skill in Antigravity, and which model ids exist (`agy models`).

## Out of scope

- The local model's role, `opencode.json`, `scripts/antigravity-cli-settings.json`, CI, app code.
- The owner's own `~/.gemini` settings.
- Historical task specs and `docs/native-app-plan.md` assignments.

## Acceptance criteria

- [ ] AGENTS.md, the workflow doc, the template and the review skill name all three tools at both tiers.
- [ ] The Antigravity hook refuses a push to `main`, `gh pr merge` and a write to a tracked migration, and answers
      nothing to ordinary commands, a new migration, a migration read and unreadable input (tests).
- [ ] `run-agent.ps1` accepts `-Model` for Antigravity without changing local runs.

## Validation

`node --test "scripts/hooks/*.test.mjs"`. Optionally one live headless Antigravity run in a throwaway repository
showing the hook refuses a harmless `git push --dry-run` to `main`. No Java change, so Maven is not needed.

## Security and regression risks

The hook must never answer `allow`. Claude Code's and Codex's guard behavior must not change.
