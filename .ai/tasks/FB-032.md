zero-additional-cost setup and reset procedure without changing the production Blueprint.

## Current behavior

- Production is configured by render.yaml. There is no hosted test environment recorded in this repository.
- FLEXBUDDY_API_ENABLED defaults to false independently of web sign-in. FB-005 adds API sign-in when enabled.
- Pages have no environment banner and responses have no test-environment noindex policy.
- offline.html is static and cached by the service worker; a template-only banner would miss it.
- flexbuddy.public-url defaults to production. A test deployment must override it so generated links stay on the
  test host.
- With no SMTP host, MailConfig uses logging mailers. Logging links/codes requires the explicit log-links override.
  Leaving FLEXBUDDY_ALERT_TO unset does not clear the configured support-address default; no SMTP host is what
  prevents outgoing alert mail.
- The entrypoint reconstructs DB_URL when DATABASE_URL is present, dropping JDBC query options. Neon must use
  DB_URL directly with TLS required and DATABASE_URL absent.

## Required behavior

### 1. Opt-in environment identity

- Add flexbuddy.test-server=${FLEXBUDDY_TEST_SERVER:false}. Keep it independent of flexbuddy.api.enabled: neither
  flag enables the other. Unset and explicit false preserve production behavior.
- When true, show a persistent, clearly readable banner on every HTML page served by the app. Include signed-out
  pages, authenticated pages, errors, legal pages, print/report views and the offline fallback/cached page shells.
  It must render without JavaScript on server-rendered pages.
- English copy: "Test server: made-up data only. Use flexbuddy.onrender.com for your real blocks."
  Spanish copy: "Servidor de pruebas: solo datos ficticios. Usa flexbuddy.onrender.com para tus bloques reales."
  Put both in the catalogs. If the host is a link, use the fixed HTTPS production URL and translate the surrounding
  text through messages; never build its destination from request input.
- Use a small reusable Thymeleaf fragment/model flag for server pages, following existing advice patterns. Avoid a
  general layout rewrite, response-body rewriting or controller-by-controller business logic.
- For /offline.html, provide a test-mode-only localized rendered variant at the existing URL (or an equally small
  solution preserving its service-worker cache contract). The normal static fallback and its behavior remain
  unchanged when the flag is false. New text comes from the catalogs; do not hard-code translated copies in JS.
  Cached shells/fallbacks fetched from the test host must retain the warning when disconnected. A fresh offline
  browser with no cached resources is not expected to load a page.
- Check desktop and phone widths, light/dark themes, 200% text and print layout. The banner must not cover controls,
  the app navigation or auth forms; meaning must not depend on color alone.
- With the flag off, omit the banner and any test-mode-only page content. No hostname guessing, production setting
  changes, new dependencies or authentication changes.

### 2. Noindex on all test-server responses

- When true, set X-Robots-Tag: noindex before downstream code can commit a response. Cover successful HTML/JSON,
  static assets, redirects, HEAD/conditional responses, errors and security short-circuits (including disabled API
  404, unauthenticated API responses and CSRF rejection). Preserve the header through error dispatches.
- Register at the servlet level early enough to cover both security chains and static resources; follow existing
  filter registration conventions. Do not weaken or reorder existing authentication, authorization or rate limits.
- With false/unset, this feature adds no X-Robots-Tag header. Keep existing response status, body, content type and
  security/cache headers intact. The banner and noindex are identification/indexing measures, not access controls.

### 3. Owner-operated hosting runbook

Add docs/test-server.md and link it from NA-11. Update only NA-11 facts that this task clarifies; avoid rewriting
unrelated sections of the native plan. The runbook must include:

1. **Cost check before creation.** Recheck official Render Free and Neon Free terms, the owner's actual workspace
   usage, and available spending controls. Select Free explicitly, with no paid add-ons or automatic upgrades.
   Render Free instance hours are shared across the workspace; bandwidth and build minutes can incur overages
   where a payment method exists. Do not promise zero additional cost based solely on the Free compute label.
   If no-cost operation cannot be established, or a new card/paid plan is required, stop hosted setup and ask the
   owner. Document the unresolved condition; continue the local code/review work independently.
2. **Separate resources.** Owner creates a Render web service through the dashboard, outside the production
   Blueprint, using this repository's flexbuddy/Dockerfile and flexbuddy Docker context, with health check
   /actuator/health. Owner creates a separate Neon Free project near the service region. Choose PostgreSQL 18 if
   available, otherwise record the supported version selected. Never connect to or clone production data.
3. **Environment checklist, names and placeholders only.** FLEXBUDDY_TEST_SERVER=true,
   FLEXBUDDY_API_ENABLED=true, FLEXBUDDY_PUBLIC_URL=<test HTTPS origin>, DB_URL=<Neon JDBC URL with sslmode=require>,
   DB_USER and DB_PASSWORD. DATABASE_URL stays absent. Owner generates fresh, stable test-only
   FLEXBUDDY_REMEMBER_ME_KEY and FLEXBUDDY_TWO_FACTOR_KEY in an interactive terminal and enters them privately.
   Never copy, display or rotate production keys. Do not inherit production environment groups/secrets.
4. **Mail and identity.** Leave every FLEXBUDDY_MAIL_* SMTP setting and both Google sign-in settings absent. Explicitly
   enable the logging mailers' flexbuddy.mail.log-links property using a verified environment override (for example
   FLEXBUDDY_MAIL_LOG_LINKS=true, confirmed with the deployed Spring configuration). Owner reads synthetic-account
   codes privately in Render logs; agents never print or copy them into artifacts/chat. No SMTP means no outgoing
   account or alert mail. Document actual alert behavior rather than claiming an unset recipient disables alerts.
   Follow ClientAddressConfig guidance for the test host without changing production settings or trusting an
   arbitrary client-supplied address header.
5. **Deployment policy.** Follow main automatically after checks pass, matching production's check gate. For an
   unmerged task, the owner deploys its approved branch explicitly. Record the deployed commit and database branch
   using nonsensitive identifiers. No agent push, merge or hosted configuration change is authorized by this spec.
6. **Repeatable data.** Create only made-up accounts and figures, with no real driver screenshots or production
   backups. Keep a clean Neon seed branch; create a disposable session branch before testing. The seed schema must
   match its recorded main baseline. For migration-bearing tasks, apply migrations only to a disposable branch.
   Returning the service to main also requires a database branch compatible with main; never downgrade Flyway,
   edit migration history or reuse an ahead-of-main database blindly. Owner verifies no service uses a disposable
   branch before deleting it. Existing sessions/tokens must be cleared or reauthenticated after database resets.
7. **Smoke check and limits.** Confirm HTTPS, health, banner/languages, noindex, synthetic web registration/sign-in
   and API sign-in/account access on the test host. Keep credentials/tokens private. Verify cold-start behavior
   after idle; Render Free currently sleeps after 15 minutes and takes about a minute to wake. Check startup and
   representative OCR memory/latency within the chosen free service limits; report limitations rather than
   purchasing resources. Local files are ephemeral. No keep-alive pings to prevent sleeping.
8. **App handoff.** Record the nonsecret test origin and known cold-start limitations for NA-03. Debug .dev builds
   may use it later; Play/release builds continue to use production. Native timeout/waking-up UI belongs to NA-03
   or the consuming app task. Do not touch the emulator's production Play install.

Pricing references, recheck at setup: https://render.com/docs/free and https://neon.com/pricing. On November 13, 2026,
the published Neon Free page lists 1 GB storage per project, 100 CU-hours per project/month and 10 included branches;

## Security and regression risks

The test server is public and noindex does not prevent access: existing auth, user scoping and limits remain required.
Filter ordering must cover early security responses without altering the two existing chains. A flag/model attribute
must not leak banner HTML into JSON, CSV, calendar files or downloads. Static offline caching and fixed-position
navigation need explicit checks. Real data and production credentials never enter the test project, database seed or
logs. Logging codes is an explicit synthetic-test-only choice. Database branch resets must preserve schema/code
compatibility; production migrations and keys are untouched.
