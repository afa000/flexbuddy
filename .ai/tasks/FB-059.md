## Objective

Let the native app show and change the driver's settings, so its Settings screen (NA-09) works without opening the
website: language, time zone, goals, tax set-aside and due-date reminders, block reminder times, mileage method and
rate, and payout days. This is the server half of NA-09. The app half (Settings screen and local reminders with
WorkManager) is a separate Android task, and NA-13 step 6 (the phone telling the server it handles reminders) comes
after both.

Mileage and payout settings are not listed in NA-09's bullet, but they are the same service and the app already reads
them (`GET /api/v1/calculation-settings`); leaving them out would send drivers to the website for half the screen.

## Current behavior

- The website reads settings with `GET /account/settings` and changes them one group at a time with the `PUT
  /account/...` endpoints above, each delegating to `AccountSettingsService`. Last write wins.
- The API exposes `GET /api/v1/account` (language and time zone among sign-in details) and
  `GET /api/v1/calculation-settings` (eight read-only calculation inputs). It has no settings write and no read of
  reminder or tax settings.

## Required behavior

### Switch and authentication

- A new `ApiAccountSettingsController` in `com.angel.flexbuddy.api`, annotated
  `@ConditionalOnProperty(name = "flexbuddy.api.enabled", havingValue = "true")`, mapped under
  `/api/v1/account/settings`. With the switch off every method on these paths returns `404` with no `Location`, and the
  website is unchanged.
- Bearer token only, through the existing `/api/v1/**` chain: missing, unknown, expired or revoked tokens and
  session-cookie-only requests return `401 {"error":"unauthorized"}` before any settings are read, compared or written.
- Every read and write uses `Principal.getName()`. No body field, header or query parameter chooses an account.
- Logic lives in a new `ApiAccountSettingsService` (api package, like `ApiExpenseService`) that maps API input to the
  website's request records and calls `AccountSettingsService`. Do not change `AccountSettingsService`'s behavior for
  the website; adding a small read helper is fine if needed.

### GET /api/v1/account/settings

200 with this complete sixteen-field body (made-up example), built from `AccountSettingsService.get`:

```json
{
  "language": "es",
  "timeZone": "America/New_York",
  "vehicleCostMethod": "standard_mileage",
  "customMileageRate": null,
  "weeklyGoal": "600.00",
  "monthlyGoal": null,
  "goalBasis": "gross",
  "payoutDays": ["tuesday", "friday"],
  "payoutLagDays": 1,
  "taxSetAsidePercent": "25.00",
  "remindTax": true,
  "remindBeforeMinutes": 60,
  "remindConfirm": true,
  "remindMiles": true,
  "askMissingMiles": true,
  "forfeitCutoffMinutes": 45
}
```

- Same field meanings, defaults and formats as `GET /api/v1/calculation-settings` for the eight shared fields
  (`customMileageRate` null in IRS mode, money with two decimals, lowercase codes, Monday-to-Sunday weekdays). Reuse its
  mapping rather than copying it.
- `language`: `en`, `es` or null (follow the device). `taxSetAsidePercent`: decimal string as stored, or null when the
  reserve is off. `remindBeforeMinutes`: one of `30`, `60`, `120`, `720`, or null when block-start reminders are off.
  `forfeitCutoffMinutes`: `0` to `720`.
- Never returned: the calendar feed path or token, the effective or default IRS rate, sign-in, two-step or Google
  details, setup-card state.
- Reading never saves anything and never creates a calendar token.
- `ApiEtags.withEtag`: strong `ETag`, `Cache-Control: private, no-cache`, `304` with an empty body on a matching
  `If-None-Match`. Any change to a returned field, from the API or the website, changes the tag.

### Writes: PUT /api/v1/account/settings/{group}

| Path | Body | Calls |
|---|---|---|
| `/language` | `{"language":"es"}` (`en`, `es` or null) | `updateLanguage` |
| `/time-zone` | `{"timeZone":"America/Chicago"}` (required IANA id) | `updateTimeZone` |
| `/goals` | `{"weeklyGoal":"600.00","monthlyGoal":null,"goalBasis":"net"}` | `updateGoals` |
| `/tax` | `{"taxSetAsidePercent":"25.00","remindTax":true}` | `updateTax` |
| `/reminders` | `{"remindBeforeMinutes":60,"remindConfirm":true,"remindMiles":true,"askMissingMiles":false,"forfeitCutoffMinutes":45}` | `updateReminders` |
| `/mileage` | `{"vehicleCostMethod":"actual_expenses","customMileageRate":"0.655"}` | `update` |
| `/payouts` | `{"payoutDays":["tuesday","friday"],"payoutLagDays":1}` | `updatePayouts` |

- **Each PUT replaces its whole group.** Nullable fields (`language`, both goals, `taxSetAsidePercent`,
  `remindBeforeMinutes`, `customMileageRate`) are cleared when absent or null. Every other field is required; absent or
  null is `400`. Codes are lower case as the API returns them; weekday codes may come in any order, duplicates are
  `400`.
- **Validation is the website's.** Build the existing request record and run its bean validation through
  `ApiWriteReceipts.valid` (or the same mechanism), so limits match the website exactly: lead minutes in
  `REMINDER_LEAD_MINUTES`, cutoff `0..720`, lag `0..14`, at least one payout day, tax percent `0.01..60` with at most
  two decimals, positive goals with at most two decimals, rate `0..5` with at most three decimals, valid time zone.
  Malformed JSON, a wrong type, an unknown code, a JSON number where the API documents a decimal string, or an invalid
  value returns `400 {"error":"invalid","fields":{"<field>":"invalid"}}` naming each bad field, and nothing is saved.
- `/reminders` keeps the account's saved time zone: pass the current zone into `ReminderSettingsRequest`, never the
  website default. `/tax` and `/reminders` always send their booleans (never null), so the website's "absent keeps
  the saved choice" does not apply to the API.
- **Conflicts use the settings ETag; no migration.** Every PUT requires `If-Match` with the ETag of the settings the
  phone last saw (from `GET` or an earlier PUT). Missing or unreadable `If-Match` returns
  `400 {"error":"invalid","fields":{"If-Match":"invalid"}}`. Under the account lock (`ApiWriteReceipts.lock`):
  1. If the tag matches the current settings, apply the change.
  2. Otherwise, if the group's current values already equal the requested ones (compare normalized values: decimals
     by `compareTo`, weekdays as a set), answer as a success without writing. This makes a retry after a lost
     response safe.
  3. Otherwise return `409 {"error":"conflict","current":{...}}`, where `current` is the full GET body, with that
     body's `ETag` header. Nothing is saved.
- `Idempotency-Key` is not required or stored for these endpoints: a group PUT is a full replacement guarded by
  `If-Match`, so the receipt table (whose check constraint allows only a block, expense or payout target) is not used.
  A key that is sent is ignored. Document this as the one exception to the Conventions bullet.
- Success returns `200` with the full GET body, its new `ETag` and `Cache-Control: private, no-cache`.
- Changing the time zone, goals, mileage or payouts also changes `GET /api/v1/calculation-settings`' tag; nothing else
  is needed for that.
- Saving the language over the API does not set the website's locale cookie. Emails already follow the saved language.
- Website writes don't take the account lock and stay last-write-wins. A website change between the phone's check and
  its write is caught by `If-Match` except for that narrow race, which is acceptable and documented.

## Acceptance criteria

- [ ] With the API on, `GET /api/v1/account/settings` returns exactly the sixteen documented keys, matching the
      website's `GET /account/settings` for the same made-up account (defaults on a new account, IRS vs custom rate,
      null goals, tax off, reminders off) and never containing a calendar path.
- [ ] Each of the seven PUTs saves its group, returns `200` with the full body and a new `ETag`, and the website's
      `GET /account/settings` then shows the change. Absent nullable fields clear; absent required fields are `400`.
- [ ] Every limit the website enforces is enforced the same way, at both edges, with `400 invalid` naming the field and
      no change saved. Malformed JSON, wrong types, unknown codes, numeric decimals and duplicate weekdays are `400`.
- [ ] `/reminders` never changes the time zone; `/tax` and `/reminders` never leave a boolean unchanged when sent.
- [ ] Missing `If-Match` is `400`; a stale `If-Match` with different values is `409` with `current` and its `ETag`, and
      nothing is saved; a stale `If-Match` whose values are already in place is `200`; a website change between GET and
      PUT is caught as `409`.
- [ ] `If-None-Match` gives `304`; any change through either the API or the website changes the tag.
- [ ] Missing or invalid tokens and session-only requests are `401` with no `ETag` and no write. Two accounts never
      see or change each other's settings; `email`/`ownerId` parameters or body fields are ignored.
- [ ] With the API off, the controller is absent and every method on `/api/v1/account/settings/**` is `404`.
- [ ] `docs/api-v1.md` documents both sections and the convention exception.

## Security and regression risks

- These writes change the inputs to earnings, net, goal and tax figures. Reusing the website's request records and
  service keeps the limits identical; a test per limit proves it.
- Authenticate before reading or comparing tags, scope to the principal, keep `Cache-Control: private, no-cache`, and
  never log tokens or settings bodies.
- The calendar feed link is private; it must never appear in an API response or log.
- The website's settings endpoints, the locale cookie and the push reminder jobs must behave exactly as before.
