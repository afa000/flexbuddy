# Task: FB-013 - Flag every net figure that's missing miles, with an Add miles shortcut

Status: Ready for implementation
Risk: medium (labels next to earnings figures and two read-only response fields; no calculation changes)
Implementer: Claude Code (Opus). The plan names Antigravity; the owner handed this task to this session on
November 5, 2026.
Review: fresh Claude Code session (Opus), review-task skill

Source: DX-03 in `docs/driver-experience-plan.md`. Builds on FB-009.

## Objective

With standard mileage, a completed block with no miles has no vehicle cost, so its estimated net is too high. FB-009
flags this on the Reports **Est. net** card and the Home **Est. net / hr** tile. Every other net figure still looks
complete: the Reports net-per-hour line, each History row's "est. net" line, the Reports breakdown table and the
gross-vs-net hourly chart. Fixing it also takes too many steps: the driver has to find the block and open it.

Every affected net figure should say it's missing miles, and a History row should offer **Add miles** straight to
that block.

## Current behavior

- Reports: **Est. net** card says "N blocks have no miles, so this is too high" (FB-009). The net-per-hour line under
  Avg hourly (`#netHourly`, "$X/hr est. net") has no flag.
- History rows: "$X est. net · $Y/hr est. net", plus the miles when entered. Nothing says a missing mileage makes the
  net too high.
- Reports breakdown table (station/week/month/year) and the gross-vs-net hourly chart: net and net/hr per group, no
  flag.
- Home: the Est. net / hr tile says "missing miles" (FB-009). Recent rows show gross per hour, not net.

## Required behavior

1. **Per-block flag (server).** `ShiftResponse` gets `netMissingMiles` (boolean, last field): true when the account
   uses standard mileage and the calculator counts this block as without miles (completed, `miles == null`). False for
   actual expenses, explicit 0 miles, and scheduled, cancelled and forfeited blocks.
2. **Per-group count (server).** `EarningsBucket` gets `netMissingMiles` (int, last field): the bucket's
   `blocksWithoutMiles` under standard mileage, otherwise 0.
3. **Reports net-per-hour line.** When `window.flexbuddyHome.netMissingMiles(statistics)` is above 0, `#netHourly`
   reads "$X/hr est. net · missing miles" (new key `js.app.netHourlyEstMissing`).
4. **History rows.** For a row with `netMissingMiles`, the est. net line ends with " · missing miles", and the row
   shows an **Add miles** text button (reuse `js.home.addMiles`; its accessible name names the station and date).
   It opens that block's edit dialog with Miles focused. The button doesn't also trigger the row's own edit button.
5. **Breakdown table and hourly chart.** A group with `netMissingMiles > 0` gets a small "missing miles" tag in its
   Net cell and its net/hr cell's text, and its chart label reads "Est. net $X · missing miles" (new key
   `js.charts.estNetMissing`). Other groups are unchanged.
6. **Rule in one place.** Server-side flags come from the calculator's existing count; the client only reads them,
   plus FB-009's `netMissingMiles(statistics)`. The client never re-derives the rule from `miles` and `status`.

## Out of scope

- Any figure or calculation: net, mileage cost, deductions, hourly rates, totals, CSV exports, tax pages. They must
  give the same numbers before and after.
- Home Recent rows (they show gross, not net), the evaluator, the Needs attention row and the finish flow's
  missing-miles list (FB-009 and earlier).
- A History filter for blocks missing miles.

## Acceptance criteria

- [ ] With standard mileage, a completed block without miles shows "missing miles" on its History line and an Add
      miles button that opens that block's dialog with Miles focused.
- [ ] Entering miles, or saving 0 miles, removes the flag and the button after the reload.
- [ ] Reports' net-per-hour line, breakdown table and hourly chart flag the groups and totals that include such a
      block, and nothing else.
- [ ] With actual expenses, nothing is flagged anywhere.
- [ ] Scheduled, cancelled and forfeited blocks are never flagged.
- [ ] Every number is unchanged; existing calculator, report, CSV and tax tests keep their expected values.
- [ ] English and Spanish text; `SpanishMessagesTest` passes.
