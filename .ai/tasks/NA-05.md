## Objective
Allow the native app outbox to create, edit, start, complete, mark not worked, delete and restore blocks safely.

## Files to read
- docs/api-v1.md and docs/native-app-plan.md, NA-05
- ShiftService, ShiftController, RequestIds and their existing tests
- API shift controllers/services/DTOs, API security and integration tests
- ShiftRepository, AppUserRepository, request DTOs, exception handling
- Latest Flyway migrations and PostgresMigrationTest

## Current behavior
API reads support change-only sync. Website writes use ShiftService; start/delete/restore have no retry keys, and edit/status remember only the last key.

## Required behavior
- Token-only /api/v1 endpoints, conditional on the existing disabled-by-default API flag.
- Use ShiftService and website request validation. Preserve status, earnings, odometer and details rules.
- Require UUID Idempotency-Key on every mutation. Persist account-scoped receipts atomically with each successful write, serializing simultaneous retries. Never reapply an old action; reject key reuse for a different action/body.
- Require expectedUpdatedAt for existing-block writes, with a structured 409 conflict for stale edits. A successful retry is acknowledged before checking the old version.
- Restore only within 30 days. No permanent-delete or batch endpoints.
- Keep change-only sync intact. Write acknowledgements identify the block; clients fetch current state through existing sync instead of advancing their cursor from an acknowledgement.
- Add a new migration for minimal receipts (no block snapshot or private payload); remove receipts on account deletion. Update docs/api-v1.md.

## Out of scope
Native app, website behavior, deployment, production data, new dependencies.

## Acceptance criteria
- [ ] All requested operations are authenticated, owned and validated through ShiftService.
- [ ] Retries, simultaneous retries, delayed retries and cross-account keys are safe.
- [ ] Stale writes conflict, failed writes do not consume keys, expired restores fail.
- [ ] Sync reports writes and deletions/restores; earnings exclude scheduled blocks.
- [ ] API errors and contract documented; tests and verification reported.

## Validation
Targeted API integration tests plus scripts/verify.ps1 -TaskId NA-05. PostgreSQL migration test only when configured; no UI change or emulator writes.

## Security and regression risks
Receipt persistence and write transactions, cross-account isolation, status/earnings rules, old backup compatibility and Recently deleted retention. No committed migration is edited.
