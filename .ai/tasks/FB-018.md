# Task: FB-018 - Keep an expense's link when it is edited

Status: Ready for implementation
Risk: medium (expense data; which block an expense belongs to)
Implementer: Claude Code (Opus). Follow-up from the FB-017 review, handed over by the owner on November 6, 2026.
Review: fresh Claude Code review (Opus, subagent), review-task skill

## Objective

Editing an expense quietly removes its link to a block when that block isn't in the form's "Shift" list: the list
only holds blocks from the current History results, never deleted ones. Saving then sends no `shiftId`, so the
expense is unlinked, and restoring a deleted block no longer links it again. FB-017 made this reachable for expenses
on deleted blocks, which now load instead of failing.

## Files to read

- `flexbuddy/src/main/java/com/angel/flexbuddy/service/ExpenseService.java`: `apply`, `ownedShift`, `linkedShiftId`.
- `flexbuddy/src/main/resources/static/js/app.js`: `editExpense`, `populateExpenseShifts`, `resetExpenseForm`,
  `saveExpense`, `expenseStationLabel`.
- Tests: `ExpenseServiceTest`, `DeletedLinkedBlockTest`.

## Required behavior

1. **Server.** An update that sends the expense's current `shiftId` keeps the link as it is, without looking the
   block up again, so a link to a block in Recently deleted survives. A different `shiftId` is still checked with
   `ownedShift` (owned, not deleted); `null` still unlinks. Creating an expense can't link to a deleted block.
2. **Form.** Opening an expense whose linked block isn't in the list adds that block as the selected option, labeled
   with `expenseStationLabel` (for example "VEA7 (deleted block)"). It stays while the expense is being edited,
   including when the date changes, and goes away when the form resets.

## Acceptance criteria

- [ ] Editing only the amount or note of an expense on a deleted block keeps the link; restoring the block shows it
      linked again.
- [ ] Choosing "No linked shift" still unlinks; choosing another owned block still links to it; linking to another
      user's block or a deleted block that wasn't already linked is refused (404).
- [ ] The form shows the kept link and doesn't lose it on a date change while editing.
