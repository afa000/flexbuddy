# Task: FB-002 - Make an Undo unusable once its notice has gone

Status: Ready for implementation

## Objective

When a driver deletes a shift, `app.js` shows a notice with an Undo button whose action restores the deleted batch.
After the notice hides, `toast.js` leaves that action attached to the button. Nothing can reach it today, because the
hidden notice is `display: none`, but any later change that lets the notice fade out while still clickable would let a
second tap run the restore again. The action should only be callable while its own notice is showing.

## Current behavior

In `flexbuddy/src/main/resources/static/js/toast.js`, `displayNext()` sets `elements.action.onclick` to a handler that
calls `hide()` and then runs `onAction`, or to `null` when the notice has no action. `hide()` hides the notice but
never clears `onclick`, so the old handler stays on the button until the next notice replaces it.

Undo is used for deleted shifts (`afterShiftDeleted` in `app.js`), edited shifts, deleted expenses, restored backups
(`account.js`) and Standing entries (`standing.js`).

## Required behavior

- `hide()` clears the action button's `onclick`, so once a notice has hidden (after its duration, on Escape, through
  `hide()`, or because its action was clicked) its action can no longer run.
- Clicking the action still hides the notice and then runs `onAction`, and a failed action still shows the "Undo failed"
  alert.
- Tests in `flexbuddy/src/test/js/toast.test.js` cover the new behavior.

## Out of scope

- Any other change to how notices look, queue or time out.
- `app.js`, `account.js`, `standing.js` and the other callers.
- CSS. (Under reduced motion the countdown bar already disappears at once; that is fine.)

## Design references

None.

## Acceptance criteria

- [ ] After a notice with an action hides, by timeout or by `hide()`, `el.action.onclick` is `null`.
- [ ] After the action is clicked, `el.action.onclick` is `null` and `onAction` has run exactly once.
- [ ] The existing toast tests still pass, including "a failed action shows Undo failed".
- [ ] In the browser on localhost, with a local test account: delete a shift, press Undo, and the shift is back in the
      history. Then delete another shift, let the notice time out (8 seconds), and the shift stays deleted (in Recently
      deleted).
- [ ] `.\scripts\verify.ps1 -TaskId FB-002` passes.

## Security and regression risks

Undo is how drivers recover a mistaken delete, so the main risk is breaking it: the browser check covers the
shift-delete path, and the existing tests cover the action call and its failure message. No server, database or
earnings change.
