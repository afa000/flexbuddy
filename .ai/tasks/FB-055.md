## Objective

NA-13 step 2 asks for Reports on the phone, computed offline from cached blocks and expenses with the shared
calculators. Today only the per-group net comes from the library (`NetEarnings`). The rest of a report lives only in
`ShiftReportService.earnings`: which expenses count, how blocks and expenses are grouped, the per-group route and
clocked-time averages, the totals and the station order. If the app rebuilt that, the money rules would be duplicated,
which AGENTS.md forbids. This is the server half: move the earnings report rollup into
`com.angel:flexbuddy-import-core` with plain inputs, and have the website use it with every figure, order and label
unchanged. The Android Reports screen is the separate app task FB-056, written once 0.5.0 is published.

## Current behavior

`GET /shifts/reports/earnings?groupBy=week|month|year|station&from&to&station&q&status` returns
`EarningsReportResponse(groupBy, from, to, buckets, totals)`:

- Blocks: `ShiftFilter.report` selection (date range inclusive, station, text query, statuses default
  `ShiftStatus.EARNINGS`).
- Expenses: the same date range, station and query through `ExpenseRepository.findFiltered`, then `countable`. An
  expense linked to a live scheduled block waits and is left out (`EarningsRules.expenseWaits`). One linked to a
  deleted block counts by its date, under no station.
- Grouping: WEEK by ISO week-based year and week (`yyyy-Www`, Monday to Sunday), MONTH (`yyyy-MM`), YEAR, and an
  "unknown" bucket for legacy rows with no date. STATION groups case-insensitively on the trimmed station. Expenses
  with no counted station go to the "unlinked expenses" bucket. Labels come from the message catalogs in the
  request's locale.
- Per bucket: block count, earned base and tips (`money`), and from `NetEarnings`: gross, minutes, hourly, miles,
  mileage cost, cash spent, deductions, net, net hourly. Also timed blocks, clocked minutes, clocked hourly, average
  finished-early minutes, blocks with route data, average stops, average minutes per stop, returns rate, and
  `netMissingMiles` (0 under ACTUAL_EXPENSES).
- Order: STATION by net descending, then label case-insensitively. Otherwise by period start, with nulls last.
- Totals: the same figures over all selected blocks and expenses.

## Required behavior

1. **Library inputs**, in `com.angel.flexbuddy.importcore.figures` (or a new `...importcore.reports` package; pick
   one and say why in the handoff), as immutable records with no Spring, locale, clock or zone:
   - a report block: the existing `Block` plus id, actual minutes, stops, packages and returns. Move the rules for
     clocked minutes, finished-early minutes, minutes per stop, returns base and returns rate into the library, and
     make `Shift`'s getters delegate to them, as `EarningsRules` already does for earned pay.
   - a report cost: the existing `Cost` plus the linked block's id, status, deleted flag and station (all null when
     unlinked). Move `countable`'s wait rule and `countedStation` into the library. `ExpenseService.countable` and
     `countedStation` keep their signatures and delegate.
2. **Selection helpers** that the app can apply to its cache, the server's SQL rules restated over plain values:
   - a block matches by inclusive date range, station (trimmed, case-insensitive equality, as
     `ShiftFilter.normalize` and the repository compare), and a status set defaulting to the `EARNINGS` statuses;
   - a cost matches by inclusive date range and linked-block station, then by the wait rule.
   The text query (`q`) is not part of the helpers: the website keeps it in SQL, and the app has no search for now.
   The server keeps selecting in SQL. Add a test that runs both paths over one made-up fixture set and asserts they
   pick the same rows, so the two can't drift.
3. **`EarningsReport`** (a name the implementer may refine): given selected report blocks, report costs, a group-by,
   the `VehicleCostMethod` and `MileageRates`, it returns buckets and totals carrying every numeric field of
   `EarningsBucket` / `EarningsTotals`, computed with `NetEarnings` and the moved rules. Use the same `money`,
   `divide` and `hourly` rounding, stated once in the library. Each bucket carries a stable key, a kind (PERIOD,
   STATION, UNLINKED, UNKNOWN_DATE), the period start and end, and the trimmed station for station buckets. It
   carries **no display label**: the server builds labels from its catalogs exactly as today, and the app will use
   its own `strings.xml`.
   - Station order needs the label for its tie-break today. Keep the website's order byte-for-byte: the library
     sorts station buckets by net descending, then by a label the consumer supplies (station text, or the consumer's
     localized "unlinked expenses" label), case-insensitively. Document this in Javadoc.
4. **Server delegation.** `ShiftReportService.earnings` selects as today, maps entities with `FigureInputs`, calls
   the library, and builds `EarningsBucket` / `EarningsTotals` with today's labels. The response JSON (field names,
   values, scales, order), the controller, routes and `reports.js` stay unchanged. `statistics`, `heatmap`,
   `payPeriods` and `goals` are untouched, except where the moved `Shift` getters now delegate.
5. **Pin first, then move.** Before moving code, add a golden JSON test: serialize `/shifts/reports/earnings` for
   every group-by, in English and Spanish, over one made-up account that covers completed, cancelled, scheduled and
   forfeited blocks; ACTUAL_EXPENSES and both mileage methods; blocks with and without miles, actual times, stops,
   packages and returns; expenses that are linked, unlinked, linked to a scheduled block and linked to a deleted
   block; mixed-case and padded stations; a legacy row with no date; ISO week 1 / week 53 around a year change; a
   station filter and a status filter. Commit the expected JSON. It must pass before and after the move. Add library
   unit tests for the same fixtures through the plain inputs and commit them as reusable fixtures, as
   `CsvExportFixtures` was, so FB-056 can use them for its parity test.
6. **Version and docs.** Raise import-core to 0.5.0 and the server's dependency to 0.5.0. Existing 0.4.0 signatures
   don't change, and nothing is tagged or published. Update import-core/README.md with a 0.5.0 reports section: the
   consumer selects only the signed-in account's rows, and labels are the consumer's. Add 0.5.0 to
   docs/import-core-releases.md as unreleased, pending owner publication. Update NA-13's status lines in
   docs/native-app-plan.md: the server half of Reports is in FB-055, and the app half is FB-056.

## Security and regression risks

These are the figures drivers use to choose stations and track net income, so any changed rounding, grouping (an ISO
week edge, a padded station), or expense counted differently (a deleted or scheduled link) is a regression. That is
why the golden test comes first. Selection stays in the server's user-scoped queries, and the library must never
receive another account's rows. Labels stay out of the library so neither platform's language catalogs fork. Use
made-up data only in fixtures; never commit a real account's report.
