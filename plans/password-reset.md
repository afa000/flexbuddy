# Password reset

Planned against `origin/main` at `32feb25` (latest migration V20, so this adds **V21**).
**It assumes `plans/sign-in-limits.md` has shipped**, because it reuses that plan's
`AttemptLimiter`.

## 1. Goal and scope

Today a driver who forgets their password is locked out for good, together with their
shift history. This plan adds the standard flow:

1. **"Forgot password?"** on the sign-in page opens a form asking for the email.
2. The driver submits it, and **always** sees the same page: "If an account uses that
   email, we've sent a link to reset its password. It expires in 30 minutes."
3. If the account exists, FlexBuddy **emails a one-time link**,
   `https://flexbuddy.onrender.com/reset-password?token=…`.
4. The link opens a form for a **new password**, entered twice, with the same 8–72
   character rule as sign-up. If the link is expired or already used, it says so and
   offers a new one.
5. **Saving the new password:**
   - uses up the link, and **cancels any other reset links** for that account;
   - **signs out every device that stayed signed in** (remember-me), the same as "Sign out
     everywhere";
   - **clears any sign-in lock** on that email;
   - goes to the sign-in page with "Your password was changed. Sign in with your new
     password."

**How the links are kept safe:**

| Rule | Detail |
|---|---|
| Random | 32 random bytes from `SecureRandom`, written base64url, about 43 characters |
| Stored safely | Only a **SHA-256 hash** is stored, never the link itself. A database leak doesn't give working links. |
| Short-lived and single-use | Expires after **30 minutes**, and works **once**. Asking again cancels older links. |
| Limited | At most **3 reset emails per email address per hour**, and **10 requests per connection per hour**. This uses the new `AttemptLimiter` buckets `reset-email` and `reset-ip`. Over the limit, the page looks exactly the same, but no email is sent. |
| Not leaked | The reset page sends `Referrer-Policy: no-referrer` and `Cache-Control: no-store`, so the link can't leak through the browser cache or a referrer header. |

**About revealing which emails have accounts:** sign-up already does that today ("An
account already uses this email."). So this flow doesn't promise to hide it. It still
gives one answer for every email, and sends the email in the background so the reply takes
the same time either way. Hiding it fully would mean changing sign-up too. That's out of
scope.

### Sending email (new to the app)

FlexBuddy can't send email today: there's no mail library or service. This plan adds
**`spring-boot-starter-mail`**, configured **only through Render environment variables**,
so no credentials go into the repo.

**Recommended provider: Gmail SMTP from `flexbuddysupport@gmail.com`**, using a Google
**app password**:
- It's free, and allows 500 emails a day, which is plenty for the closed test and early
  production.
- It needs no domain of your own. Services like Brevo, Resend or Postmark need a verified
  domain to deliver reliably, and `onrender.com` isn't yours.
- **What you'd do in Google:** turn on 2-Step Verification for `flexbuddysupport@gmail.com`,
  create an app password named "FlexBuddy", and paste it into Render. Section 7 has the
  steps.

Moving to a domain-based provider later only changes the environment variables.

**Locally, and anywhere mail isn't configured,** the app starts fine and uses a mailer that
writes "password reset requested; mail is not configured" to the log. **It logs the link
itself only when `flexbuddy.mail.log-links=true`**, a setting that's off by default and
meant only for local development. A production log must never contain working links.

### Out of scope

- Changing a password while signed in. That's a natural next step, and the same
  `PasswordService` can serve it later.
- Verifying email addresses at sign-up.
- Changing the email address.
- HTML emails (plain text is more reliable to deliver).
- Ending other devices' current browser sessions immediately (see section 9).
- Hiding which emails are registered (see above).

## 2. Data model and migration

**New file `V21__password_reset.sql`.** Don't edit any existing migration.

```sql
create table password_reset_token (
    id bigint generated by default as identity primary key,
    owner_id bigint not null references app_users(id) on delete cascade,
    token_hash char(64) not null,
    created_at timestamp(6) with time zone not null,
    expires_at timestamp(6) with time zone not null,
    used_at timestamp(6) with time zone,
    constraint uk_password_reset_token_hash unique (token_hash)
);
create index idx_password_reset_token_owner on password_reset_token (owner_id);
```

**New `model/PasswordResetToken.java`**, shaped like `PayoutDeposit`:

- `@ManyToOne(fetch = LAZY, optional = false) @JoinColumn(name = "owner_id") @OnDelete(action = CASCADE) AppUser owner`.
  The `@OnDelete` gives the H2 test schema the cascade too.
- `@Column(name = "token_hash", length = 64, nullable = false, unique = true) String tokenHash`
- `Instant createdAt`, `Instant expiresAt`, `Instant usedAt` (nullable)

**New `repository/PasswordResetTokenRepository.java`:**

```java
Optional<PasswordResetToken> findByTokenHash(String tokenHash);
@Modifying @Query("update PasswordResetToken t set t.usedAt = :now where t.owner.id = :ownerId and t.usedAt is null")
int retireUnused(@Param("ownerId") Long ownerId, @Param("now") Instant now);
@Modifying @Query("delete from PasswordResetToken t where t.expiresAt < :cutoff")
int deleteExpiredBefore(@Param("cutoff") Instant cutoff);
@Modifying @Query("delete from PasswordResetToken t where t.owner.id = :ownerId")
int deleteAllByOwnerId(@Param("ownerId") Long ownerId);
```

Reset links aren't backed up. They're temporary, and a restored account asks for a new one.

## 3. Backend

### Dependency and configuration

**`pom.xml`:** add `org.springframework.boot:spring-boot-starter-mail`. Its version comes
from the Spring Boot parent.

**`application.properties`.** Every value comes from the environment, with safe defaults:

```properties
spring.mail.host=${FLEXBUDDY_MAIL_HOST:}
spring.mail.port=${FLEXBUDDY_MAIL_PORT:587}
spring.mail.username=${FLEXBUDDY_MAIL_USERNAME:}
spring.mail.password=${FLEXBUDDY_MAIL_PASSWORD:}
spring.mail.properties.mail.smtp.auth=true
spring.mail.properties.mail.smtp.starttls.enable=true
spring.mail.properties.mail.smtp.connectiontimeout=10000
spring.mail.properties.mail.smtp.timeout=10000
flexbuddy.mail.from=${FLEXBUDDY_MAIL_FROM:FlexBuddy <flexbuddysupport@gmail.com>}
flexbuddy.mail.log-links=false
flexbuddy.public-url=${FLEXBUDDY_PUBLIC_URL:https://flexbuddy.onrender.com}
flexbuddy.security.reset.max-per-email=3
flexbuddy.security.reset.max-per-ip=10
flexbuddy.security.reset.window=1h
flexbuddy.security.reset.link-valid-for=30m
```

**Important:** with an **empty** `spring.mail.host`, Spring Boot still creates a
`JavaMailSender`. Choose the mailer by checking
`StringUtils.hasText(spring.mail.host)`, not by whether the bean exists.

**`render.yaml`:** add `FLEXBUDDY_MAIL_HOST` (value `smtp.gmail.com`), `FLEXBUDDY_MAIL_PORT`
(`587`), and `FLEXBUDDY_MAIL_USERNAME` and `FLEXBUDDY_MAIL_PASSWORD`, both with
**`sync: false`**. `sync: false` makes Render ask for the value in its dashboard and never
store it in the file. **Never put the app password in the repo.**

### Mail

**New `mail/PasswordResetMailer.java`**, an interface:
`void sendResetLink(String toEmail, String displayName, String link)`.

**Two implementations, chosen by a `@Configuration` `MailConfig`:**

- **`SmtpPasswordResetMailer`**, when the mail host is set:
  - Builds a `SimpleMailMessage` (plain text) from `flexbuddy.mail.from`.
  - Subject: **"Reset your FlexBuddy password"**.
  - Body:

    ```
    Hi {displayName},

    Someone asked to reset the password for your FlexBuddy account. To choose a new
    password, open this link within 30 minutes:

    {link}

    If you didn't ask for this, you can ignore this email. Your password won't change.

    FlexBuddy
    ```

  - **Errors are caught and logged** as "password reset email could not be sent", without
    the address or the link. They're never shown to the visitor, whose page looks the same
    either way.
- **`LoggingPasswordResetMailer`**, when no host is set: logs one INFO line. It includes
  the link **only** if `flexbuddy.mail.log-links=true`.

**Sending in the background:**

- `@EnableAsync`, on `SchedulingConfig` or a new `AsyncConfig`.
- A small `ThreadPoolTaskExecutor` bean, `mailExecutor`: core 1, max 2, queue 50.
- `sendResetLink` runs `@Async("mailExecutor")`, so the request returns straight away,
  whether an email is sent or not.

### `service/PasswordResetService.java`

Constructor: the token repository, `AppUserRepository`, `PasswordEncoder`,
`PersistentTokenRepository`, `AttemptLimiter`, `PasswordResetMailer`, `Clock`, and the
properties for the public URL and the reset limits.

**`requestReset(String rawEmail, String ip)`**, `@Transactional`:

1. Normalise the email with `trim().toLowerCase(Locale.ROOT)`.
2. If `reset-ip` or `reset-email` is locked, **return** (no email).
3. Otherwise record both buckets.
4. `userRepository.findByEmailIgnoreCase(email)`. If there's no account, **return**.
5. `tokenRepository.retireUnused(user.getId(), now)` cancels older links.
6. Make a token: 32 bytes from a `SecureRandom` held in a field, then
   `Base64.getUrlEncoder().withoutPadding()`.
7. Save its **SHA-256 hex hash** with `expiresAt = now + 30m`.
8. `mailer.sendResetLink(user.getEmail(), user.getDisplayName(), publicUrl + "/reset-password?token=" + token)`.

**`checkToken(String token)`** returns `Optional<AppUser>`: hash the token, find it, and
accept it only if `usedAt == null && expiresAt.isAfter(now)`.

**`resetPassword(String token, String newPassword)`**, `@Transactional`:

1. Check the token as above. If it's invalid, throw `InvalidResetTokenException`.
2. `user.setPasswordHash(encoder.encode(newPassword))`.
3. Mark the token used, and `retireUnused(user.getId(), now)` for any others.
4. `persistentTokenRepository.removeUserTokens(user.getEmail())`, which signs out
   remember-me devices.
5. `limiter.clear("login-email", email)`, which lifts any sign-in lock.

**`@Scheduled(cron = "0 45 4 * * *")` `purgeExpired()`:**
`deleteExpiredBefore(now − 1 day)`. It lives here rather than in `ShiftPurgeJob`, so that
job's constructor and its test don't change.

### Controller: new `controller/PasswordResetController.java` (`@Controller`)

| Route | Behaviour |
|---|---|
| `GET /forgot-password` | `forgot-password.html` with an empty form. `?sent` shows the confirmation instead. |
| `POST /forgot-password` | Validates `@Email @NotBlank @Size(max=254)`. A badly formed email shows the field error. Otherwise calls `requestReset(email, request.getRemoteAddr())` and **always** redirects to `/forgot-password?sent`. |
| `GET /reset-password?token=…` | A valid token gives `reset-password.html` with a hidden `token` field. An invalid or missing token gives `reset-password-invalid.html` ("This link has expired or was already used." plus a **Send a new link** button to `/forgot-password`). Both set `Cache-Control: no-store` and `Referrer-Policy: no-referrer`. |
| `POST /reset-password` | Takes `token`, `password` and `confirmPassword`. Checks the password is 8–72 characters and the two match; otherwise it shows the field errors on the same form, with the token kept. On success calls `resetPassword`, then redirects to `/login?reset`. An invalid token shows the invalid page. |

**New DTOs:**
- `ForgotPasswordRequest(String email)`;
- `ResetPasswordRequest(String token, String password, String confirmPassword)`, with
  `@AssertTrue isMatching()` and the same `@Size(min = 8, max = 72)` message as
  `RegistrationRequest`.

### `SecurityConfig`

Add `/forgot-password` and `/reset-password` to the `permitAll` list. CSRF stays on: both
forms are Thymeleaf forms and carry the token.

### Account deletion

In `AccountService.deleteAccount`, call
`passwordResetTokenRepository.deleteAllByOwnerId(ownerId)` with the other owned tables,
before the user is deleted.

- `AccountService` gets a constructor parameter, so **`AccountServiceTest`** (which uses
  `@InjectMocks`) needs a `@Mock` and an `InOrder` step.
- **`AccountDeletionJpaTest`** saves one token and asserts `rowCount("password_reset_token")`
  is 0.

## 7. Manual checks

**Setting up email, which you do once. It's outside the code:**

1. Sign in to Google as `flexbuddysupport@gmail.com`, then go to Security and turn on
   **2-Step Verification**.
2. Go to Security, then **App passwords**, and create one named "FlexBuddy". Copy the
   16-character password. **Don't paste it anywhere except Render.**
3. In Render, open the flexbuddy service, then Environment, and set:
   - `FLEXBUDDY_MAIL_HOST` = `smtp.gmail.com`
   - `FLEXBUDDY_MAIL_PORT` = `587`
   - `FLEXBUDDY_MAIL_USERNAME` = `flexbuddysupport@gmail.com`
   - `FLEXBUDDY_MAIL_PASSWORD` = the app password

   Save, which redeploys.

**Checks after the deploy:**

4. **Request a reset** for your own account from the sign-in page.
   - The page says "If an account uses that email…".
   - An email from "FlexBuddy" arrives within a minute. Check spam too.
5. **On the Android phone,** tap the link in Gmail. It opens **in the FlexBuddy app**, not
   in a browser tab, because Android hands the site's links to the app. The new-password
   form shows.
6. **Mistakes:** mismatched passwords, or one 7 characters long, each show an error and keep
   the form.
7. **Save a new password.**
   - You land on sign-in with "Your password was changed…".
   - The old password fails, and the new one works.
   - **Another phone that was signed in** is signed out the next time it opens the app.
8. **Open the same link again:** "This link has expired or was already used", with **Send
   a new link**.
9. **Expiry:** request a link, wait 31 minutes, then open it. It shows the invalid page.
10. **An unknown email** shows the same page, and no email arrives.
11. **Limit:** 4 requests for the same email within an hour. Only 3 emails arrive, and the
    page is identical each time.
12. **Lock and reset together:** lock your email with 5 wrong passwords, then reset the
    password. The new one signs in straight away, with no 15-minute wait.
13. **Logs:** in Render's logs, search for `reset-password?token`. **No matches.**
14. **Phone layout:** the three new pages at 375px have no horizontal scroll, and fields
    and buttons are at least 44px.

## 8. Suggested commit message

```
feat(auth): let drivers reset a forgotten password by email

The sign-in page now has a Forgot password link. Asking for a reset
always shows the same page, and if the email has an account FlexBuddy
sends a link that works once and expires after thirty minutes. Only a
hash of the link is stored, asking again cancels older links, and no
more than three emails an hour go to one address.

Choosing a new password signs out every device that stayed signed in,
lifts any sign-in lock on the account, and returns to the sign-in page.
Email is sent through Gmail's mail server from the support address,
with its password kept in the server's environment rather than the
code, and the app still starts without it, logging that mail is not
set up. Links are removed from the database a day after they expire
and when the account is deleted, and the privacy policy says how reset
emails are sent.
```

## 9. Open questions

1. **Email provider.** Is Gmail SMTP from `flexbuddysupport@gmail.com` with an app
   password all right? It's free and needs no domain. The alternative is a provider such
   as Brevo or Resend, which needs a domain you own.
2. **Other devices' open sessions.** A reset signs out *remembered* devices, but a browser
   tab that's open right now stays signed in until its session ends (about 30 minutes idle
   by default). Fixing that means tracking every session, which is a bigger change. Is
   that acceptable for now?
3. **Link lifetime.** Is 30 minutes all right? Some services use 15 minutes, some an hour.
